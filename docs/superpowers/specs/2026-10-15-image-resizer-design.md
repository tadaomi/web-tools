# 画像リサイズツール 設計書

- 作成日: 2026-10-15
- 対象: `src/tools/image-resizer/`（Web便利ツール集の1ツールとして新規追加）
- 元実装: `src/tools/image-resizer/zip_image_resizer.html`（単体HTML・Tailwind CDN・JSZip CDN）

## 1. 目的と前提

### 目的

CMS 用サムネイル（基準 170px）を、ZIP にまとめた画像から一括で作成する。主用途はこの定型作業で、ときどき任意サイズの汎用リサイズにも使う。

### 成功基準

- 170px のサムネイル作成は「ZIP をドロップ → ZIP をダウンロード」の2操作で完了する（前回の設定を復元するため毎回の設定は不要）。
- 汎用用途では、設定を変えて「再処理」を押せば、ファイルを入れ直さずに結果を作り直せる。
- 元実装の機能（向きごとのルール・出力形式・画質・命名規則・フォルダ構成の保持・プレビュー・個別保存）をすべて引き継ぐ。
- 元実装の不具合（第6章）をすべて解消する。
- 既存ツールと同じ構成・見た目（CSS 変数・ダークモード対応）・規約（1ディレクトリ完結・registry 登録・localStorage キーの命名）に従う。

### 前提

- すべての処理をブラウザ内で行い、画像はサーバーに送信しない。
- 画像そのものは保存しない。設定だけを localStorage に保存する。
- 元の `zip_image_resizer.html`（git 管理外）は、完成後に削除する。

## 2. 決定事項の一覧

| 項目           | 決定                                                                                  |
| -------------- | ------------------------------------------------------------------------------------- |
| 入力           | 「ZIP 1つ」または「画像を複数」。混在・ZIP 2つ以上は受け付けない                      |
| 出力           | 常に ZIP でまとめてダウンロード。各画像の個別保存もできる                             |
| 小さい画像     | 「小さい画像は拡大しない」の ON/OFF。既定は OFF（拡大して基準にそろえる）             |
| 処理タイミング | 投入したらすぐ処理。設定を変えたら「再処理」ボタンを出し、押したときだけ処理し直す    |

| 画像処理       | メインスレッドで `createImageBitmap` と Canvas。1枚ごとに UI へ制御を返す             |
| 追加の依存     | `fflate` のみ                                                                         |
| テスト         | ブラウザに依存しない処理ロジックを Node 標準の `node --test` で検証（追加の依存なし） |

## 4. データの流れ

1. **入力の判定**（DropZone → ImageResizer）
   - 拡張子 `.zip`（または MIME に `zip` を含む）なら ZIP、`jpg/jpeg/png/webp/gif/bmp` なら画像と判定する。
   - 受け付けるのは「ZIP が1つだけ」か「画像だけを1つ以上」のどちらか。それ以外はメッセージを出して受け付けない。
2. **展開**
   - ZIP: `readZip(bytes)` が `{ entries: [{ path, bytes }], skipped }` を返す。`skipped` は除外した件数。
   - 画像: `{ path: file.name, bytes }` の形にそろえる。
   - 並び順: `path` を数字を考慮した並び（`localeCompare(…, 'ja', { numeric: true })`）でソートする。
   - 展開した元データ（`sourceEntries`）は、再処理に使うためメモリ上に保持する。
3. **処理**（1枚ずつ順番に）
   - `resize.js` でデコード → `dimensions.js` でサイズを計算 → Canvas に描画 → エンコード → `naming.js` で出力パスを決める。
   - 1枚ごとに `onProgress(current, total)` を呼び、`setTimeout(0)` で UI へ制御を返す。
   - 失敗した画像は飛ばし、`{ path, error }` として結果に残す。
4. **結果**
   - 成功: `{ srcPath, outPath, blob, url, srcW, srcH, outW, outH, srcSize, outSize, notes[] }`
   - `notes` は「GIF→PNG」「WebP非対応のためPNGで出力」などの注意。
5. **出力**
   - ZIP 名: ZIP を入れたときは `<元のZIP名>_resized_<size>px.zip`、画像を入れたときは `images_resized_<size>px.zip`。
   - ZIP 内のパスは `outPath`（元のフォルダ構成を保持）。
6. **再処理**
   - 最後に処理したときの設定（スナップショット）を保持し、今の設定と違うあいだは「設定が変更されました」と「再処理」ボタンを表示する。
   - 再処理・新しい入力・リセット・画面を離れたときは、既存の結果のプレビュー用 URL（Object URL）をすべて解放する。

## 5. 処理ルール

### 5.1 設定項目と既定値

| 設定                      | 値                                                            | 既定                                            |
| ------------------------- | ------------------------------------------------------------- | ----------------------------------------------- |
| 基準サイズ                | 16〜4096 px の整数                                            | 170                                             |
| 横長（幅 > 高さ）のルール | `width` / `height` / `longest` / `shortest` / `crop` / `none` | `width`                                         |
| 縦長（高さ > 幅）のルール | 同上                                                          | `height`                                        |
| 正方形のルール            | `fit` / `none`                                                | `fit`                                           |
| 小さい画像は拡大しない    | ON / OFF                                                      | OFF                                             |
| 出力形式                  | `original` / `image/png` / `image/jpeg` / `image/webp`        | `original`                                      |
| 画質（JPEG / WebP）       | 0.4〜1.0、0.05 刻み                                           | 0.9                                             |
| 命名規則                  | `original` / `suffix` / `prefix` / `numbering`                | `original`                                      |
| 追加する文字列            | 任意の文字列                                                  | 命名規則に応じて `_170px` / `resized_` / `img_` |

- 基準サイズが範囲外・数値でないときは、16〜4096 に丸めた値を使う（空欄なら 170）。
- 追加する文字列は「自分で編集したか」のフラグを持つ。未編集のときは、命名規則の変更や基準サイズの変更に合わせて既定値を入れ直す（`suffix` は `_<size>px`）。
- 追加する文字列に含まれる `/ \ : * ? " < > |` は `_` に置き換える。

### 5.2 サイズ計算（`dimensions.js`）

`calcDimensions(srcW, srcH, settings)` → `{ outW, outH, crop: { sx, sy, sw, sh } | null }`

- 向きの判定: `srcW > srcH` なら横長、`srcH > srcW` なら縦長、等しければ正方形。EXIF の回転情報を反映したあとの縦横で判定する。
- `width`: 幅を基準に、高さは比率で計算。`height`: その逆。`longest` / `shortest`: 長辺 / 短辺を基準に、もう一方を比率で計算。
- `crop`: 中央の「短辺×短辺」を切り抜き、`基準×基準` に縮小・拡大する。
- `fit`（正方形）: `基準×基準`。`none`: 元のサイズのまま。
- 比率で計算する辺は `Math.round` で丸め、最小 1px とする。
- **拡大しない（ON）**: 計算した倍率が 1 を超える場合は倍率を 1 にする（元のサイズのまま）。`crop` では短辺が基準より小さければ、出力は `短辺×短辺`（切り抜くだけ）。

### 5.3 縮小処理（`resize.js`）

- デコード: `createImageBitmap(blob)`（EXIF の回転は既定で反映される）。失敗したら「画像を読み込めませんでした」で失敗扱い。
- 描画: 切り抜き範囲を出力サイズへ描画する。縮小後の2倍以上の大きさがある間は、Canvas 上で半分ずつ縮め、最後に出力サイズへ描画する（`imageSmoothingQuality = 'high'`）。
- JPEG で出力するときは、先に白で塗ってから描画する。
- エンコード: `canvas.toBlob(mime, quality)`。`null` が返ったら「画像の書き出しに失敗しました（メモリ不足の可能性があります）」で失敗扱い。
- 使い終わった `ImageBitmap` は `close()` し、Canvas は幅・高さを 0 にして解放を促す。

### 5.4 出力形式と拡張子

- 書き出す形式:
  - 出力形式が `original` のとき、**拡張子で判定する**。`jpg/jpeg` → JPEG、`png` → PNG、`webp` → WebP、`gif/bmp` → PNG（`notes` に「GIF→PNG」「BMP→PNG」を追加する。アニメーション GIF は最初の1コマになる）。
  - それ以外のときは、指定した形式で書き出す。
- **出力の拡張子は、実際に書き出された `blob.type` で決める**（`image/jpeg` → `.jpg`、`image/png` → `.png`、`image/webp` → `.webp`）。
  - ただし `original` で、元の拡張子と実際の形式が一致する場合は、元の拡張子の表記を保つ（`.JPEG` → `.JPEG`）。
  - 指定した形式と `blob.type` が違う場合（WebP に対応していないブラウザ）は、`notes` に「WebP非対応のためPNGで出力」を追加する。
- 画質は JPEG / WebP にだけ渡す。設定 UI では、出力形式が PNG のとき画質スライダーを無効にする。

### 5.5 ファイル名（`naming.js`）

- 出力パス = 元のパスのフォルダ部分 + 新しいファイル名。
- `original`: `<元の名前>.<拡張子>`、`suffix`: `<元の名前><文字列>.<拡張子>`、`prefix`: `<文字列><元の名前>.<拡張子>`、`numbering`: `<文字列><番号>.<拡張子>`。
- 番号: 成功した画像だけで、処理順（4章のソート順）に 1 から振る。桁数は `max(3, 総数の桁数)` でゼロ埋めする。
- 重複回避: 同じフォルダ内で、大文字・小文字を区別せずに出力名を比較する。重なった場合は `<名前>-2.<拡張子>`、`-3`… と番号を付ける。
- ZIP 名とファイル名に使う元の名前は、ZIP に入っていた名前（フォルダ部分を除く）を使う。

### 5.6 ZIP の読み込み・作成（`zipio.js` / `filename.js`）

- fflate は `import('fflate')` で使うときに初めて読み込む（PDF ツールの `pdfjs.js` と同じ方式）。
- 展開: `unzipSync(bytes, { filter })` を使う。`filter` で次のものを除外し、除外した件数を数える。
  - 名前が `/` で終わるもの（フォルダ）
  - パスのどこかに `__MACOSX` を含むもの
  - ドット（`.`）で始まるファイル名・フォルダ名を含むもの（どの階層でも）
  - 拡張子が `jpg/jpeg/png/webp/gif/bmp` 以外のもの
- ファイル名の救済（`filename.js`）: fflate は UTF-8 の印がないファイル名を1バイト＝1文字（latin1）として読む。そこで、すべての文字コードが 0〜255 で、かつ 0x80 以上を含む名前は、バイト列に戻す。そのうえで `TextDecoder('utf-8', { fatal: true })` で読めればそれを、読めなければ `TextDecoder('shift_jis')` の結果を使う。
- 作成: `zipSync(files, { level: 0 })`（無圧縮）。画像はもともと圧縮済みのため。
- 壊れた ZIP は「ZIPを読み込めませんでした。破損していないか確認してください。」で通知する。

## 6. 元実装の不具合と対応

| #   | 不具合                                                                                                                        | 対応                                                   |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 1   | 「元の形式を維持」で、JSZip から取り出した Blob の MIME タイプが空のため、すべて PNG で書き出される（拡張子は `.jpg` のまま） | 拡張子で形式を判定する（5.4）                          |
| 2   | GIF/BMP の中身が PNG になり、拡張子と食い違う                                                                                 | 実際に書き出した形式で拡張子を決める（5.4）            |
| 3   | 透過画像を JPEG にすると背景が黒くなる                                                                                        | 白で塗ってから描画する（5.3）                          |
| 4   | 小さい画像も必ず拡大される                                                                                                    | 「拡大しない」の ON/OFF（5.2）                         |
| 5   | 出力名が同じになり、ZIP 内で上書きされる                                                                                      | 重複回避（5.5）                                        |
| 6   | Shift_JIS の日本語ファイル名が文字化けする                                                                                    | 救済デコード（5.6）                                    |
| 7   | 連番が失敗した画像の分だけ飛ぶ／サブフォルダ内の隠しファイルを除外しない                                                      | 成功した画像だけで採番（5.5）／どの階層でも除外（5.6） |
| 8   | 設定を変えても反映されず、入れ直しが必要                                                                                      | 再処理ボタン（4章）                                    |
| 9   | ファイル名を `innerHTML` に埋め込んでいる（XSS の余地）                                                                       | Svelte のテキスト展開で表示する                        |

## 7. 画面の構成

最大幅 960px、余白などは PDF ツールに合わせる。色・角丸・影は `app.css` の CSS 変数だけを使う（ダークモードは自動で対応される）。

1. **見出し**: 「画像リサイズ」と「🔒 すべてブラウザ内で処理されます。画像はサーバーに送信されません。」
2. **使い方**（`<details>`、既定は閉じる）: 3ステップ（設定 → 投入 → ダウンロード）と、向きごとのルールの説明。
3. **設定パネル**（`SettingsPanel.svelte`）
   - 1段目: 基準サイズ（数値入力）・出力形式（選択）・画質（スライダーと % 表示）
   - 2段目: 横長・縦長・正方形のルール（選択×3）
   - 3段目: 「小さい画像は拡大しない」（チェックボックス）
   - 4段目: 命名規則（選択）・追加する文字列（`original` のときは隠す）・ファイル名の例（`sample.jpg` に今の設定を適用した結果）
4. **ドロップ領域**（`DropZone.svelte`）: 「ZIP または画像をドラッグ＆ドロップ、またはクリックして選択」。ファイルを入れたあとは「`photos.zip` ・ 画像42件（除外3件）・別のファイル」の1行表示に切り替える。
5. **進捗**: 進捗バーと「12 / 42 枚」。
6. **設定変更のお知らせ**: 「設定が変更されました」と「再処理」ボタン。
7. **結果**（`ResultGallery.svelte`）
   - 見出し行: 「成功 N 件 / 失敗 M 件」・合計サイズ（元 → 新）・「ZIPをダウンロード」ボタン
   - カードの一覧（`grid-template-columns: repeat(auto-fill, minmax(150px, 1fr))`）: 市松模様の背景にプレビュー、新しい縦横サイズ、出力名、変わっていれば元の名前、元の縦横サイズ、ファイルサイズ、`notes`、「保存」ボタン。
   - 失敗した画像は、`--danger` の枠のカードで元のパスと理由を表示する。

処理中は、設定パネル・ドロップ領域・「別のファイル」・「再処理」・「ZIPをダウンロード」を無効にする。

## 8. エラー処理

| 状況                                                     | 動き                                                                |
| -------------------------------------------------------- | ------------------------------------------------------------------- |
| ZIP・画像以外のファイル、ZIP が2つ以上、ZIP と画像の混在 | 画面内にメッセージを出し、受け付けない                              |
| ZIP が壊れている                                         | 「ZIPを読み込めませんでした。破損していないか確認してください。」   |
| 処理できる画像が0件                                      | 「処理できる画像が見つかりませんでした（除外 N 件）」               |
| 個別の画像のデコード・エンコードに失敗                   | その画像を失敗として結果に残し、残りの処理を続ける                  |
| ZIP の生成に失敗                                         | 「ZIPの作成に失敗しました。」                                       |
| 処理中の再操作                                           | 関係する操作をすべて無効にして、同時に2つの処理が走らないようにする |

処理を途中で止める（キャンセル）機能は付けない。
